# XSAI Release Export

Use this skill for customer-facing `release_*.tar.gz` packages that combine
source trees, generated RTL and simulation collateral, and test binaries.

## Workstream

This is an `xsai-env` base/tools workflow. The export script builds XSAI RTL
through the XSAI Makefile, then collects source trees and generated collateral;
it should not change subsystem contracts.

Primary files:

- `scripts/export-release.sh`
- `XSAI/build/release-DefaultMatrixConfig/` generated by the export
- optional generated output directories passed to that script
- `.agents/skills/xsai-release-export/SKILL.md` when updating this guide

Do not edit `XSAI/`, `NEMU/`, `nexus-am/`, or generated RTL just to make the
package shape work. The RTL source must be the current `XSAI/` checkout built
by the script with `CONFIG=DefaultMatrixConfig`; external RTL release trees are
not valid substitutes.

## Release package shape

The target archive root should look like:

```text
<release-name>/
├── Makefile
├── Release-XSAI-YYYYMMDD/
│   ├── RELEASE-METADATA
│   ├── XSAI.f
│   └── rtl/
│       └── XSTop.sv
├── NEMU/
├── nexus-am/
├── env/
│   ├── difftest/
│   ├── generated-src/
│   ├── sim/
│   └── sram_tb/
├── cases/
├── riscv-openocd/
├── toolchain/
│   ├── bin/
│   │   ├── xsai-clang
│   │   └── xsai-clang++
│   ├── llvm/
│   ├── riscv64-linux-gnu/
│   ├── lib/gcc/riscv64-linux-gnu/
│   ├── README.md
│   └── TOOLCHAIN-METADATA
└── sram_tb.mk
```

Current mapping:

| Package path | xsai-env source/input | Kind |
|---|---|---|
| `Makefile` | generated by `scripts/export-release.sh` | release harness |
| `NEMU/` | `NEMU/` | source subtree |
| `nexus-am/` | `nexus-am/` | source subtree |
| `env/difftest/` | `XSAI/difftest/` | source subtree |
| `Release-XSAI-YYYYMMDD/` | current `XSAI/`, built as `DefaultMatrixConfig`, one core, synthesis `XSTop` | generated collateral |
| `env/generated-src/` | generated difftest output | generated collateral |
| `env/sim/` | generated simulation Verilog output | generated collateral |
| `cases/` | built/prebuilt test `.bin` payloads | binary collateral |
| `env/sram_tb/`, `sram_tb.mk` | SRAM testbench helper collateral | release collateral |
| `riscv-openocd/` | external OpenOCD source snapshot | vendored dependency |
| `toolchain/llvm/` | selected tools, shared libraries, and clang resource headers from `local/llvm/` | host compiler toolchain |
| `toolchain/riscv64-linux-gnu/` | detected `RISCV_SYSROOT` headers and libraries | RISC-V Linux target sysroot |
| `toolchain/lib/gcc/` | runtime located through `riscv64-linux-gnu-gcc` | RISC-V target runtime |

## Standard export command

For a full package when all generated inputs are already available:

```bash
scripts/export-release.sh \
  --name release_YYYYMMDD_<tag> \
  --output-dir local/release \
  --cases-dir path/to/cases \
  --generated-src-dir path/to/generated-src \
  --sim-dir path/to/sim \
  --sram-tb-dir path/to/sram_tb \
  --sram-tb-mk path/to/sram_tb.mk \
  --openocd-dir path/to/riscv-openocd \
  --strict
```

Use `--dry-run` first when paths are uncertain:

```bash
scripts/export-release.sh --dry-run --name release_probe
```

Without `--strict`, missing optional collateral is warned and skipped. Use
`--strict` for customer handoff packages so incomplete archives fail early.
RTL is never optional: the script runs the equivalent of
`make -C XSAI verilog CONFIG=DefaultMatrixConfig NUM_CORES=1 ISSUE=E.b` in the
isolated `XSAI/build/release-DefaultMatrixConfig/` build directory. The package
names that RTL directory `Release-XSAI-YYYYMMDD`, using the UTC date captured
once when the export script starts.

The compiler toolchain is also required. Do not copy only standalone LLVM
binaries: this installation links against `libLLVM` and `libclang-cpp`, while
clang also needs its resource headers. The export therefore stages a curated
runtime installation plus the RISC-V Linux sysroot and GCC runtime. It omits
LLVM static development libraries, CMake metadata, and unrelated tools.

## Verification

Always verify through the package surface, not only by reading the script:

1. Run script help and syntax checks:

   ```bash
   bash -n scripts/export-release.sh
   scripts/export-release.sh --help
   scripts/export-release.sh --dry-run --name release_probe
   ```

2. Create a real archive into `local/release/` or `/tmp/opencode/...`.

3. Check required paths inside the tarball:

   ```bash
   tar -tzf local/release/<release-name>.tar.gz <release-name>/Makefile
   tar -tzf local/release/<release-name>.tar.gz <release-name>/NEMU/Makefile
   tar -tzf local/release/<release-name>.tar.gz <release-name>/nexus-am/Makefile
   tar -tzf local/release/<release-name>.tar.gz <release-name>/env/difftest/Makefile
   tar -tzf local/release/<release-name>.tar.gz <release-name>/Release-XSAI-YYYYMMDD/RELEASE-METADATA
   tar -tzf local/release/<release-name>.tar.gz <release-name>/Release-XSAI-YYYYMMDD/XSAI.f
   tar -tzf local/release/<release-name>.tar.gz <release-name>/Release-XSAI-YYYYMMDD/rtl/XSTop.sv
   tar -tzf local/release/<release-name>.tar.gz <release-name>/toolchain/bin/xsai-clang
   tar -tzf local/release/<release-name>.tar.gz <release-name>/toolchain/llvm/bin/clang
   tar -tzf local/release/<release-name>.tar.gz <release-name>/toolchain/TOOLCHAIN-METADATA
   ```

4. Summarize the output path and package size:

   ```bash
   du -sh local/release/<release-name>.tar.gz
   ```

## Common pitfalls

- DefaultMatrixConfig RTL generation is a heavy XSAI build and may take tens
  of minutes or longer. The isolated build directory prevents another
  configuration in `XSAI/build/rtl` from being mistaken for release RTL.
- Run `make llvm` before exporting when `local/llvm` is absent. The packaged
  compiler is an x86_64 GNU/Linux host build; it is not portable to macOS,
  Windows, Arm hosts, or arbitrarily old glibc distributions.
- The RISC-V sysroot and GCC runtime come from the detected local cross
  toolchain. Keep the staged license/copyright files with customer packages.
- Current `xsai-env` may not have generated `env/generated-src`, `env/sim`,
  `env/sram_tb`, or `riscv-openocd` at the repo root. That is expected; pass
  explicit paths or build/generate them first.
- `cases/` is binary collateral, not the AM source tree. Do not substitute
  source directories when the customer expects runnable `.bin` payloads.
- Existing submodule dirtiness in `XSAI`, `NEMU`, or `nexus-am` belongs to the
  user or another workflow. Do not clean it as part of export.
